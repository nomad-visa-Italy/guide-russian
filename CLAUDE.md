# CLAUDE.md — Гайд по визе цифрового кочевника в Италии

## Что это за проект

Русскоязычный гайд по визе Digital Nomad (цифровой кочевник) в Италии. Источники: официальные документы + дампы Telegram-чатов. Аудитория — русскоязычные соискатели визы.

**Не художественный текст — фактический справочник.** Каждое утверждение должно иметь источник и дату.

## Система маркировки — ОБЯЗАТЕЛЬНА

Каждое фактическое утверждение в гайде **должно** иметь маркер надёжности:

| Маркер | Значение |
|--------|---------|
| 🟢 | Официально — из законодательства, сайтов консульств, integrazionemigranti.gov.it |
| 🟡 | Из опыта — подтверждено реальными кейсами, но не закреплено официально |
| 🔴 | Спорно — противоречивая информация или разные исходы у разных людей |

**Формат:** `🟢/🟡/🔴 Текст утверждения. | [Источник] | Дата`

### Форматы ссылок на источники

- `[Чат #1234]` — сообщение в основном DN-чате (nomadvisaitaly)
- `[emigrantista #1234]` — сообщение в emigrantista_answers
- `[immigrazia_IT #1234]` — сообщение в immigrazia_IT
- `[rutoitaly #1234]` — сообщение в rutoitaly
- `[rutoitalychat #1234]` — сообщение в rutoitalychat
- `[@ne_putai/1234]` — пост в личном канале
- `[VMS Москва]` — italy-vms.ru
- `[Консульство Москва]` — consmosca.esteri.it
- `[Gazzetta Ufficiale]` — официальный вестник Италии
- URL — другие внешние источники

## Требования к обновлению данных

### Что делать с новой информацией

1. **Новая информация** → добавить в нужный раздел с маркером, источником, датой
2. **Подтверждение существующего** → добавить дополнительный источник/кейс к имеющейся записи
3. **Противоречие с существующим** → сохранить оба варианта, пометить 🔴 Спорно, указать даты обоих
4. **Новое отменяет старое** → обновить основной текст, старое вынести в примечание как устаревшее
5. **Устаревшая информация** → пометить с датой и описанием нового положения дел

### Чего не делать

- **Не переписывай** существующий текст без причины — только добавляй, уточняй, корректируй
- **Не удаляй** существующие записи без явного опровержения новыми данными
- **Не домысливай** — нет данных → пометь «требует уточнения»
- **Не обобщай** — «в Италии всё сложно» не является фактом гайда

### Обязательный контекст для каждого факта

- **Где**: консульство / визовый центр / квестура / город
- **Кто**: тип занятости (ИП / наёмный), гражданство если влияет
- **Когда**: дата события или сообщения (процедуры меняются)

### Различай

- Факт: «визу дали за 2 недели» vs Мнение: «это консульство самое быстрое»
- Визовый центр ≠ консульство (ВЦ — посредник, решение за консульством)
- «Виза D» ≠ DN-виза (виза D — общая категория, DN — один из подтипов)

### После изменений — проверка через git diff

Убедиться, что каждая **удалённая** строка либо заменена эквивалентом, либо обоснованно опровергнута. Ни одна существующая запись не должна быть потеряна без причины.

## Два рабочих процесса (скилы в .claude/skills/)

### 1. Обновление из основного DN-чата

Скил: `.claude/skills/update-guide/SKILL.md` — триггерится автоматически при запросе на обновление гайда из дампа nomadvisaitaly.

Процесс: разбивка `result.json` на треды → **поиск полных кейсов → вставка в `15-cases.md`** → извлечение фактов → обновление гайда.

Дампы в `.datasource/YYYY-MM-DD/nomadvisaitaly_YYYY-MM-DD/`. Самая новая папка — источник новых данных. Предыдущие — референс для контекста и для resolve cross-period replies.

### 2. Извлечение из внешних чатов (разреженные данные)

Скил: `.claude/skills/extract-sparse-data/SKILL.md` — триггерится при запросе на обработку внешних чатов.

Чаты: emigrantista_answers, immigrazia_IT, rutoitaly, rutoitalychat. Только ≤1% сообщений релевантны DN. Алгоритм: grep по tier-1/2/3 паттернам → расширение контекста → **обязательная верификация DN-релевантности** → извлечение.

**Критично:** без верификации Tier 2 триггеры дают ~50% ложных срабатываний (lavoro autonomo, фриланс без DN-контекста). Верификация — `DN_VERIFY_RE` по объединённому тексту всей дискуссии.

Результаты сохраняются в той же папке что исходник: `extracted_<source_name>.json`.

**Дополнительно:** даже если сообщение не проходит полный DN_VERIFY, но содержит личный кейс подачи/получения — вставить его в `15-cases.md` (кейс ценен сам по себе).

## Раздел 15-cases.md

Раздел содержит **только сами кейсы** — исходный текст, оставленный людьми. Никакого шаблона, никаких инструкций агенту, никакого форматирования поверх оригинала.

- Кейсы идут от **новых к старым**
- Формат кейса — как написал автор, без переработки
- Добавлять кейс = вставить исходный текст сообщения/треда целиком, с датой и ссылкой на источник
- Не реструктурировать и не «улучшать» чужой текст

### Что включать в 15-cases.md

**Включаем:**
- Кейсы получения визы **DN (Digital Nomad / lavoratore da remoto)**
- Кейсы получения **ВНЖ DN** после въезда
- Кейсы **al seguito** для членов семьи DN-заявителя
- Сводки и статистика, где DN — основная часть данных

**Не включаем:**
- Кейсы исключительно по визе **Lavoro Autonomo (LA)** — гайд фокусируется на DN
- Если кейс упоминает LA только как сравнение или предысторию (подавались на LA → получили DN) — включаем, это DN-кейс
- Если источник содержит смешанный пост (LA + DN) — включаем, описывая в заголовке оба мотива

### Приоритет при обработке любых данных — ОБЯЗАТЕЛЕН

**При обработке любых источников** (основной чат, внешние чаты, дампы, отдельные сообщения) — **в первую очередь** искать полные кейсы подачи/получения визы DN или ВНЖ DN и вставлять их в `15-cases.md`. Это приоритетнее обновления других разделов гайда.

**Что считается полным кейсом** (достаточно одного из):
- Человек описывает получение визы DN от начала до конца (документы → подача → решение)
- Человек описывает получение ВНЖ DN после приезда (квестура → permesso → итог)
- Человек описывает значимый этап с деталями: консульство, тип занятости, даты, результат

**Сигналы в тексте** — искать по этим паттернам:
- «получил визу», «одобрили», «отказали», «визу дали», «получил пермессо», «ВНЖ получил»
- «подал документы», «прошёл собеседование», «отправил пакет»
- «моя история», «делюсь опытом», «расскажу как», «у меня получилось»
- «консульство [город]», «квестура [город]» + конкретный результат

**Алгоритм**:
1. При сканировании источника — сначала выделить все потенциальные кейсы
2. Проверить: есть ли личный опыт + результат (положительный или отрицательный) + хоть какие-то детали
3. Если да → вставить исходный текст в `15-cases.md` перед обновлением других разделов
4. Если кейс уже есть в `15-cases.md` (по совпадению источника и ID сообщения) — не дублировать

## Качество контента

- Информация **сильно варьируется по регионам** — всегда указывай город/консульство/квестуру
- Более **свежая информация приоритетнее** при конфликте (но старую не удалять)
- Ранняя информация (2024) помечается «на момент запуска программы»
- Факты из **внешних чатов, подтверждающие** основной чат = независимая верификация, особо ценна
- **Нейтрализуй эмоции**: «эта %$# квестура потеряла документы» → «Квестура X потеряла документы заявителя»
